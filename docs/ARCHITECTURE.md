# Architecture

## Runtime topology

```
                       ┌──────────────────────────── Vercel (one origin) ───────────────────────────┐
Browser ──HTTPS──►     │  static SPA (React)          rewrites: /api/*  /sitemap.xml  /media/* ──┐  │
                       └────────────────────────────────────────────────────────────────────────┼──┘
                                                                                                  ▼
                                                          FastAPI on Railway ──► PostgreSQL (Railway)
                                                                 │  └──► Cloudinary (media uploads)
                                                                 └──► SMTP (Brevo): lead + security mail
```

**Why the rewrite:** admin auth uses HttpOnly cookies. If the SPA called the Railway domain directly the cookies would be third-party and blocked by Safari/Chrome. Proxying `/api/*` through Vercel makes every call same-origin, so cookies can be `SameSite=Lax` and CORS is not needed for the browser at all (CORS stays configured, deny-by-default, for the legacy cross-origin contact form).

## Backend layout (`backend/`)

```
app/
  main.py                 app factory: middleware, routers, error handlers, /health, /ready, /sitemap.xml
  core/
    config.py             typed env settings; production startup guard (refuses weak/missing secrets)
    database.py           SQLAlchemy 2 engine/session, transaction-per-request dependency
    security.py           Argon2id hashing, JWT, refresh-token & CSRF helpers, TOTP (Fernet-sealed secrets)
    permissions.py        permission catalogue, role → permission map, require_permission() dependency
    deps.py               current-user / session / reauth dependencies
    errors.py             AppError hierarchy + uniform error envelope
    logging.py            JSON-ish structured logs with request_id
    ratelimit.py          slowapi limiter + proxy-aware client IP
    email.py              SMTP sender with retries + templates
    storage.py            media storage adapters (Cloudinary, local-dev)
    audit.py              audit-log writer
  models/                 SQLAlchemy models (one module per domain)
  schemas/                Pydantic request/response models
  services/               business logic shared by routers (auth, leads, media, content, sitemap)
  api/v1/
    auth.py               login / refresh / logout / me / reauth / password reset / invite / MFA
    public.py             read-only published content + contact + testimonial submission
    admin/                one router per module; generic CRUD factory for simple resources
  cli.py                  `python -m app.cli create-admin | seed | ...`
  seed/                   development + content-migration seed data
alembic/                  migrations (the only schema-change path)
tests/                    pytest against a real PostgreSQL test database
```

Layering rule: routers validate input + check permissions → services hold logic → models persist. Simple CRUD resources share a tested generic implementation instead of 15 hand-copied routers (less code = fewer access-control mistakes).

## Frontend layout (`frontend/src/`)

```
main.tsx                  QueryClient + Router
lib/api.ts                fetch wrapper: same-origin, credentials, CSRF header, refresh-on-401, typed errors
lib/queries.ts            TanStack Query hooks for public content
lib/icons.tsx             whitelisted icon registry (CMS stores an icon *key*, never markup)
components/               existing visual components, now fed by API data
pages/                    Home, About, Services, ServiceDetail, Projects, ProjectDetail, Blog, BlogPost, Contact, NotFound
admin/                    lazy-loaded bundle: layout, auth guard, DataTable, ResourceForm, module pages
```

- Public routes are lazy-loaded; the admin bundle is never downloaded by visitors.
- Content edits appear on the next query (no rebuild). Public queries use a short stale time.
- Markdown is rendered with `react-markdown` **without** raw HTML, so CMS content can never inject script.
- SEO tags use React 19 native `<title>/<meta>/<link>` hoisting; sitemap is generated by the API.

## Content flow

Admin edit → `PUT /api/v1/admin/...` (cookie + CSRF + permission check) → transaction → audit log row → public `GET /api/v1/public/...` returns only `published`, non-deleted rows.

## Compatibility

- `POST /api/contact` (old form contract) keeps working and now also stores the lead.
- `/health` unchanged; `/ready` added (checks the database).
- Bundled `/resume.pdf` and project images remain as fallbacks until media is uploaded through the admin.

## Known architectural limits

- SPA: crawlers that do not execute JavaScript see the shell only. Google renders JS; social preview bots get the default OG tags from `index.html`. Pre-rendering is a documented follow-up.
- Rate limits and the login throttle are in-process (single Railway instance). Use Redis (`RATE_LIMIT_STORAGE_URI`) before scaling out.
